# Implement the ProTube video catalog

**Approved on:** 2026-10-17
**Approved by:** Project team review required
**Used for:** Implementing the Browse Video List user story (US-04)

## Prompt

You are a senior full-stack software engineer working on the ProTube monorepo. Implement
the Browse Video List user story from `REQUIREMENT.md` so authenticated and
unauthenticated users can discover videos generated by the `tooling/videoGrabber`
utility or uploaded by users.

Before modifying files, inspect `AGENTS.md`, `README.md`, `REQUIREMENT.md`,
`DEVELOPMENT.md`, the existing video controller, application service, input and output
ports, frontend API hook, frontend components, the media resource configuration, and
the video grabber output format. Follow the existing controller-service-port-adapter
architecture and reuse existing dependencies and conventions.

Replace placeholder video values with a file-backed catalog that reads the directory
configured by `ENV_PROTUBE_STORE_DIR`. Treat the `.json`, `.webp`, and `.mp4` files
with the same numeric identifier as one catalog entry. Return a stable API response
containing the identifier, title, description, duration when available, thumbnail URL,
and video URL. Do not expose local filesystem paths to the frontend.

Handle incomplete or invalid entries explicitly: do not publish an entry when its
metadata is malformed, its required title is missing, or its thumbnail or video file
is unavailable. Log a warning for skipped entries and make a missing store directory
behave predictably according to the existing application conventions. Do not silently
turn an unexpected store read failure into a successful response.

Update the frontend so it renders the returned catalog as accessible video cards with
the thumbnail, title, description, and optional duration while preserving loading and
error states. Keep media URLs compatible with the backend `/media/**` resource handler.

Add focused tests for the domain/application/controller contract and the file-backed
adapter, including a valid video, missing media, malformed metadata, and an empty or
missing store. Update frontend tests and snapshots for the new response shape. Do not
implement video detail playback, authentication, search, upload, or unrelated
refactors in this task.

After implementation, update the Catalan exam study guide in
`docs/GUIA_ESTUDIO_EXAMEN.md` and its Word export with the functional behavior,
architecture decisions, error handling, tests, and exam points. Preserve this prompt
in `prompts/` and reference it in the AI change log and the eventual conventional
commit. Validate the smallest relevant backend and frontend test/build commands.

## Notes

The current video grabber produces one `.mp4`, one `.webp`, and one `.json` file per
video. The JSON contains the title and commonly contains the description under
`meta.description` and the duration at the top level. The configured store directory
must remain the single source of truth; never add a hardcoded local path or commit
generated media.
